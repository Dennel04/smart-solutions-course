## 5. Vastused по частям

### Osa 1 — Robot

- **Адреса:** робот 192.168.1.6, станция 192.168.1.40 (`Ethernet 2`), маска 255.255.255.0, шлюз пустой. По инструкции нужен .50, у нас .40: та же подсеть, работает. Ping 4/4, 0–1 мс.
- **Порты:** 29999 (dashboard-команды), 30003 (движение), 30004 (обратная связь каждые 8 мс), все открыты (`Test-NetConnection`, 03.10.26).
- **DO:** DO2 = всасывание, DO1 = выдув. Проверено импульсами DO с датчиком давления MPX5700AP (02.10.26).
- **Позиции** (`data/positions.json`): из прогона 02.10 — X 259, Y 27, R −72, стекло Z −103, «над» Z −83. Источник и гнездо в одной точке (подъём на месте).
- **10 подъёмов** (`docs/pick_test.csv`): 10/10, вакуум при подъёме −52.7…−55.1 кПа.
- **Что было не так в базовом пакете** (PR https://github.com/KKallas/mg400-base/pull/2):
  1. Рука уходила в alarm 34 (J3 > 105°) и 73 (параллелограмм) → модель кинематики останавливает раньше, кнопка Recover.
  2. **ServoP только по R не исполняется.** Опыт: цель R −27 при неподвижном XYZ → рука 4 с стоит в IDLE на −27.98. С 0.5 мм по X R поворачивается, но останавливается, когда X приехал (−27.29 при цели −28). Из-за этого буквы падали по таймауту 15 с. Исправление: если XYZ на месте, а R отличается > 0.2°, один `MovJ` в ту же точку. Проверено: ошибка 0.007°, ~1 с.
  3. Ползунки слали команду на каждое движение → движение по отпусканию, jog-кнопки, Sync.
  4. Пол Z только при старте → меняется во время работы (присоска −105, ручка −112).
  5. `localhost` на Windows сначала пробует IPv6 → +200 мс на запрос; используем 127.0.0.1.

### Osa 2 — Ekraan

- **Прошивка:** PlatformIO, `m5stack-atoms3`, заливка ~17 с.
- **Сеть:** `AtomFramer`, пароль `atomframer` (сменить перед уходом из лаборатории!), 192.168.4.1, страница `http://192.168.4.1/`.
- **Captive portal (Android, 03.10.26):** страница открылась сама. Телефон спрашивал `http://connectivitycheck.gstatic.com/generate_204` (7 раз за ~минуту), `favicon.ico`, плюс фоновое приложение `c.whatsapp.net/chat`. iPhone не проверяли.
- **Картинка 128×128** (32 768 Б RGB565): приём по Wi-Fi 77 / 72 мс, запись + экран 246 / 254 мс → ~0.33 с на Atom (`docs/atom_page.md`).
- **Найдено и исправлено:**
  - во встроенном окне Android прокрутка вверх перезагружала страницу, картинка терялась → CSS `overscroll-behavior-y: contain`, отправка из Chrome;
  - в режиме букв картинка не видна: экран = кнопка, сеть на нём не рисует → переключатель в настройках;
  - лог Atom мог принять от Wi-Fi-клиента перевод строки и подделать строку буквы → управляющие символы заменяются на `?`;
  - часть строк лога в USB обрезается (вероятно, теряются байты USB-CDC) — известный недочёт.
- **Настройки и тесты** на странице: SSID/пароль, адрес станции, режим букв, тест экрана, тест буквы (`docs/atom_page.md`).

### Osa 3 — Täht

- **Канал** (`docs/letter_channel.md`): Atom → USB JSON `{"letter","session","seq","atom_sent_ms"}` → `atom_bridge.py` → HTTP POST `127.0.0.1:5000/api/letter` → станция → mg400-base `:8000` → MG400. Дубли отсеиваются по `session`+`seq`.
- **Буквы** (`docs/letters.md`): ручка вверх Z −100, вниз −112, R −28°, 20 %. Буквы 20 мм = план 20 мм (замер линейкой). A, L, N — из `letters.json`, остальные — однолинейный шрифт.
- **Лист:** утром углы (335,−118)/(335,146); после перестановки робота безопасная зона (215,−103)…(215,132), 235 × 148 мм, вся досягаема (~2200 точек проверено через `/api/check`).
- **Latency** (`docs/latency.csv`, 5 нажатий, задание требует 30): Atom → станция ср. 4.4 / макс. 12.2 мс (относительно: у Atom свои часы); станция → первая команда роботу ср. 493.7 / макс. 592.2 мс (проверка досягаемости всех точек буквы перед движением).
- **Найдено и исправлено:**
  - таймаут 15 с не хватал на длинный переезд при 4 % (280 мм ≈ 35 с) → таймаут считается от расстояния;
  - допуск ручки 0.15 мм применялся и к R в градусах → у R свой допуск 0.3°;
  - ручка перелетала по Z на 0.7 мм (2 %) / 1.3 мм (4 %), потому что XY начинался до остановки Z → ждать Z ±0.15 мм.
